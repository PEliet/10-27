# 《这破能力也能赢？》

纯前端中文卡牌策略小游戏。开局抽取一种超能力；正式模式由用户配置的大模型一次生成本局三关蓝图，本地 TypeScript 规则引擎负责卡牌、资源、机制、伤害和胜负。

## 两种模式

### 正式 AI 动态局

- 必须先在网页内配置自己的 OpenAI 兼容 API。
- 抽取能力后，模型一次生成有前后联系的三关，而不是逐关临时换故事。
- 生成界面显示真实阶段：正在构思三关 → 检查规则 → 检查难度。
- 蓝图通过 Zod、语义检查和三种简单策略模拟后才会开局并写入 v3 存档。
- 不合格蓝图会带着具体错误交给模型修复，最多两次；仍失败时明确显示错误，可重新生成或进入离线示例。
- 后两关不会提前展示，规则生成后固定，不会根据玩家表现提高目标或增加隐藏规则。

### 离线示例局

- 无需 API Key 和网络，可完整玩三关。
- 使用项目内经过协议与模拟检查的固定蓝图快照。
- 页面始终标注“离线示例局”，不会伪装成实时 AI 生成。
- 每种能力都有独立示例，便于验证整局能力机制。

生成失败不会覆盖原有有效存档；只有新蓝图通过检查并正式进入战斗后，才会保存为当前进度。

## 回合玩法

- 24 点生命跨关继承，每回合 3 点能量并抽至 4 张手牌。
- 点击卡牌立即本地结算；同回合不会自动补牌。
- 进度达到目标立即通关，不再执行该回合威胁。
- 护盾抵消威胁伤害，并在下一回合清零；机巧上限为 5。
- 当前威胁、伤害、打断阈值和关卡机制始终公开。
- 第一、二关后从蓝图校验过的三个真实卡牌 ID 中选择奖励，也可跳过。
- 第一关后额外进行一次超能力成长二选一；随后选择恢复 6 点生命或升级一张牌。
- 每关可完整重试一次，恢复进入该关时的生命、牌组和能力成长，蓝图保持不变。

开局会保证起手包含基础推进牌，第一回合同时保证防御选择。规则引擎会复查手牌位置、费用和能力条件，快速连点同一张牌不会重复结算。

## 整局超能力

能力规则由本地程序固定实现，AI 只能为它设计适配关卡。

### 三秒撤回

- 被动：每回合首次打出的非消耗付费牌会被记录。
- 主动：每关一次，把本回合已进入弃牌堆的记录牌放回手牌。
- 不返还能量；重打仍需正常付费；消耗牌不能回收，因此不会形成无限循环。
- 成长方向：重打时获得护盾，或将每关次数增加到两次。

### 临时减重

- 被动：每回合首次打出实际费用不超过 1 的牌后，下一张付费牌费用 -1，最低为 1。
- 主动：每关一次，使下一张付费牌费用变为 0。
- 被动与主动减费不能叠加；主动未在本回合使用会消失。
- 成长方向：被动减费可跨回合保留，或每回合首次消耗减费时获得机巧。

### 物品翻译

- 被动：除当前公开意图外，再显示下一回合意图和抽牌堆顶一张牌。
- 主动：交换抽牌堆顶两张牌并获得机巧，实际改变后续抽牌顺序。
- 成长方向：扩大未来意图与牌顶预览，或增加主动次数与机巧收益。

战斗页常驻紧凑能力栏，显示被动说明、主动按钮、剩余次数、当前可用条件和所选成长。减费、记录、撤回状态也会直接标在卡牌上。

## 蓝图协议

模型不能生成代码，项目不使用 `eval`、`new Function` 或脚本解释器。可执行字段只允许以下有限协议：

- 触发：出牌后、结束回合、回合开始。
- 条件：卡牌类型、单回合推进、护盾、机巧、出牌数、指定回合。
- 效果：增加进度/护盾/机巧、下一张牌减费、承受伤害、减少进度/机巧。
- 持续：立即结算或保持到下一张牌使用。
- 上限：每回合一次或每关一次。

每个机制包含可读说明。模型提供的机制摘要和威胁描述不是规则真源；蓝图通过检查后，前端会根据条件、效果、伤害和打断阈值重新生成标准中文说明，保证玩家看到的数值与本地结算一致。场景叙事如果夹带“每回合造成数值伤害”等可执行规则表达，仍会被校验拒绝。

蓝图还包含：本局标题与背景、三个目标与意图序列、能力互动机会、至少两条内部策略路线、收益与代价、卡池覆盖、关间奖励候选和结局事实。内部路线用于检查，不向玩家直接泄露解法。

校验内容包括：

1. 恰好三关，能力 ID 与固定能力钩子一致。
2. 目标、伤害、蓄力、打断阈值、机制效果均在预算内。
3. 卡牌、资源、条件和效果 ID 已由程序实现。
4. 第一关只教学基础伤害与能力核心，不引用未获得卡牌。
5. 奖励引用真实且属于当前能力的卡池。
6. 机制与意图的玩家说明由结构化字段本地重建，故事不夹带规则。
7. 三关目标递增，每关至少两条有收益与代价的策略说明。
8. 使用积极推进、保守防御、能力协同三种简单策略运行本地模拟，筛除明显无解、卡死或过度必胜的蓝图。

轻量模拟只是明显问题筛选，不宣称数学证明所有关卡完全平衡。

## AI 文风与旁白

关卡提示词要求用具体人物动作、物件和麻烦建立场景，开场约 60—100 字；禁止功能介绍口吻、营销文案、空泛称号、强行升华和常见套话。数值规则与故事分开展示。

正式局结束回合后可异步请求一句 20—50 字旁白：

- 卡牌与威胁已经先由本地引擎结算，旁白不能覆盖状态。
- 出牌和主动能力不等待网络。
- 超时、取消、空内容、网络或跨域失败都不扣次数、不修改结算。
- 响应绑定局号与关卡，旧局响应不能污染新局。
- 离线示例局不请求 AI 旁白，避免混淆“固定快照”和“实时生成”。

## 技术架构

- Vite + React + TypeScript + Tailwind CSS
- Zod 校验动态蓝图和 v3 游戏存档
- Vitest 覆盖 API、协议、三种能力、本地规则和模拟器
- `html-to-image` 生成战绩卡
- 无后端、API Route、Serverless Function、数据库或代理
- 浏览器直接向用户配置的 OpenAI 兼容接口发送请求
- 静态页面服务不处理 API 请求，也不保存 Key

## 环境与启动

需要 Node.js 20+ 和 npm 10+。

```bash
npm install
npm run dev
```

默认地址：<http://127.0.0.1:5173>。

Windows 可双击 `start.bat`。macOS/Linux 首次执行 `chmod +x start.sh`，之后运行 `./start.sh`。脚本会检查 Node/npm、按需安装依赖并启动本地静态网页服务。

常用检查：

```bash
npm run typecheck
npm run lint
npm test
npm run build
npm run preview
```

项目不承诺直接双击 `file://` 下的 `index.html` 可运行。

## 网页内配置 DeepSeek

1. 点击首页或战斗页的“模型设置”。
2. 服务商选择 DeepSeek。
3. Base URL 默认 `https://api.deepseek.com`。
4. 填入自己的 API Key。
5. 模型默认 `deepseek-flash`，可根据账户实际可用模型手动修改。
6. 先点“测试连接”，再点“保存并使用”。测试会产生少量 API 用量。

地址规范化兼容基础地址、带 `/v1` 的地址和完整 `/chat/completions` 地址。请求使用非流式 Chat Completions；DeepSeek 请求显式关闭思考模式，避免生成预算被推理内容耗尽。

连接测试使用短普通文本。正式蓝图使用 8000 token 输出预算和 90 秒单次超时，并在启用设置时优先请求 `response_format: {"type":"json_object"}`；只有服务端明确拒绝该参数时才自动降级一次，网络、超时、截断或服务异常不会自动重试。JSON/规则/难度不合格的蓝图最多定向修复两次。

如果请求在“构思三关”阶段失败，错误面板会显示不含 Key 的模型、请求主机与路径、HTTP 状态、耗时、结束原因和摘要，便于区分输出截断、超时、浏览器网络/跨域和上游服务错误。

设置中的连接诊断展示主机、路径、模型、HTTP 状态、耗时、结束原因与可见字符数，不包含 Key、请求头或完整原始响应。

2026-10-28 已使用用户临时提供的真实凭证完成一次验证：浏览器从 `http://127.0.0.1:5173` 直连 DeepSeek 成功，返回模型 `deepseek-flash`；随后真实生成一局“物品翻译”三关蓝图，首轮校验要求修复一次，第二轮通过规则和三策略模拟。测试后未持久化凭证并已清除页面内存。不同账户、模型和部署来源的余额、权限及跨域策略仍可能不同。

项目不使用 `no-cors`、公共 CORS 代理或后端转发，也不会伪造连接成功。

## Key 与本地存储

Key 默认只保存在当前页面内存，刷新后消失。只有主动选择“记住到本机”，才会以可读取形式保存到当前浏览器 `localStorage`；这不是加密保险箱。

存储项相互分离：

- 非敏感模型配置
- 用户主动记住的 Key
- v3 游戏进度与完整已验证蓝图
- 最近五局主题摘要（不含 Key，用于减少重复）
- UI 偏好

设置页可以分别清除 Key、当前进度或本项目管理的全部本地数据。战绩卡、复制战报、日志、URL 和连接诊断均不包含 Key。修改 API 地址后必须重新保存，不会自动向新地址发送请求。

## 静态部署与手机

```bash
npm run build
```

将 `dist/` 上传到 GitHub Pages、Cloudflare Pages、Netlify、Nginx 等静态托管即可，不需要服务端函数。

手机的 `localhost` 指向手机自己。推荐部署后通过 HTTPS 地址访问；同一局域网临时测试可运行 `npm run dev:lan`，再访问 `http://电脑局域网IP:5173`。该命令使用 `--host 0.0.0.0`，会向局域网开放，只应在可信网络使用。

手机和电脑的存档、配置与 Key 不会自动同步。

## 主要代码

- `src/ai/blueprint.ts`：生成提示词、真实阶段、JSON 解析和最多两次定向修复
- `src/game/blueprint.ts`：Zod 协议、语义/预算/文风校验
- `src/game/simulator.ts`：三种简单策略的本地轻量模拟
- `src/game/state.ts`：卡牌、能力、结构化机制、威胁、奖励、重试与原子结算
- `src/data/offlineBlueprints.ts`：明确标注的离线示例快照
- `src/data/content.ts`：三种固定能力及成长方向，不再包含正式预设关卡表
- `src/ai/api.ts`：地址规范化、请求、JSON兼容降级、错误诊断与短旁白
- `src/App.tsx`：生成流程、四卡战斗、能力状态栏、奖励和存档协调
